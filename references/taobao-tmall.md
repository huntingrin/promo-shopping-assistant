# 淘宝天猫规则范围与核验

规则适配版本：`taobao-tmall-v2`；资料查阅日期：2026-10-21。

本文件是本项目的规则整理与覆盖说明，不是平台官方发布的统一算法。Skill 对不同 Agent 保持通用；购物平台只支持淘宝、天猫国内普通购物。程序没有内置任何“2026双11默认满减”或默认立减比例。

## 交易域、店铺与付款阶段

- 商品 `platform=taobao` 为统一淘宝交易域，包含淘宝店与天猫店；`marketplace=taobao/tmall` 记录实际店铺类型。输入 `platform=tmall` 时自动规范为淘宝交易域，并标记天猫店。
- 优惠 `platform=taobao` 不额外限制店铺类型；淘宝店专属/天猫店专属用 `marketplaces` 明确限制。优惠输入 `platform=tmall` 是天猫专属范围的简写，不代表另一个独立结算域。其余店铺、SKU、品类与活动标签条件仍以 AND 方式共同生效。
- 相同 `checkout_group` 表示已经确认当前可以合并的批次。店铺类型不单独决定能否合并；实际不能同批付款的阶段、渠道分配不同组。默认组只用于已确认可同批付款的普通购物；未确定时先保存阻塞问题，不通过改组猜测规则。
- 预售商品录入完整售卖价和实付定金，不能只录尾款；是否可在当前阶段与现货合并，以当前购物车及尾款流程核实。
- 天猫国际、跨境税费、淘宝闪购/外卖、充值卡等特殊交易暂不作为本版可求解场景。若出现特殊费用或规则，保留原材料并说明范围。

这些是本程序的建模约定，不构成平台保证。每个当前候选SKU和优惠均需有材料来源。

## 当前覆盖与处理方式

| 规则/材料 | 当前处理 | 本次必须确认 |
| --- | --- | --- |
| 优惠前商品活动价、明确的固定售卖价 | 可计算；记录 `price_kind=before_order_promotions` | SKU、数量、价格口径、账户资格、时点 |
| 只有“预计到手价”/券后价 | 保存为 `after_coupons` 并阻止求解 | 展开优惠明细，补齐优惠前价格，避免再减一遍 |
| 只有预售尾款 | 保存为 `tail_payment` 并阻止求解 | 完整售卖价、实付定金、已确定的预售立减 |
| 店铺/商品满减券、店铺满减 | 可按明确范围、门槛、减免、次数及互斥求解 | 哪些SKU适用，哪些条件属于整单限制，是否已领取且当前可用 |
| 跨店满减 | 本次确有该活动时可建模，不自动添加 | 活动标识与档位、参与商品、基数、封顶、自动执行与叠加说明 |
| 品类券、88VIP满额减额券 | 符合现有满减语义时可建模 | 是否确为满额减额券，店铺类型、SKU范围、用户资格、可用次数与互斥 |
| 官方立减/单品直降 | 支持明确固定单品价或percentage比例规则；不得重复录入同一优惠 | 比例、基数、逐件/整单舍入、封顶、执行阶段及前后优惠是否已包含 |
| 按比例官方立减、88VIP折扣、满件/阶梯折扣 | 已有比例、件数门槛、最高满足档位、每N件减额、逐件/整单舍入、单次及共享封顶模型 | 当前资格、比例、基数、作用层级、舍入、分摊与叠加语义 |
| 红包、淘金币、支付立减 | 支持共享金额/积分、明确换算步长、单次比例/金额上限、支付阶段固定/比例优惠；用后扣减 | 是否可拆用、是否可选择金额、实际可用余额/积分、资格、顺序、运费是否可抵 |
| 购物金/储值卡本金 | 不作为免费优惠，尚无完整资金成本模型 | 已付资产与额外权益须区分，不能把付款方式当折扣 |
| 运费/包邮、已付定金 | 固定店铺运费和已有定金可计算 | 实际收货地区、包邮基数、拆单后运费、已实付金额；未知运费阻止计算 |
| 有价券/购券成本、返现/赠券、退货凑单 | 不做完整优化，不把券购买成本或后返现金当作免费优惠 | 已发生费用与后续条件需独立模型；当前保留为未支持条件 |

“可建模”表示程序有对应语义，不表示任意名称相同的活动都符合该语义。整单全部商品必须适用可用whole_checkout，最低件数用min_quantity；不要仅以商品过滤器替代这类约束。详细参数、示例及记账协议见 [discounts.md](discounts.md)。

## 当次规则核验清单

Agent 从浏览器购物车、商品详情、优惠说明或用户现有材料直接提取可确定的信息，只补问会改变购买方案的项目：

1. 当前活动/渠道、资料时间，商品SKU、店铺类型、数量，以及用户可用的账户权益。
2. 价格是订单优惠前的活动价、固定单品优惠后的价、预计券后价还是尾款；每个关键金额保留来源。
3. 每张券的实际可用状态、适用商品、门槛口径、执行顺序、互斥、账户剩余次数、时效和资格。
4. 商品能否同批结算、是否存在不同付款阶段或渠道限制；运费与包邮条件。
5. 是否还有会影响金额但程序尚不能表达的权益。将未解决项写为 `questions` 中 `blocking=true`，核实后解除。
6. 用结算预览逐项回核，记录可观察差异，再更新输入。预览不等于已买；只有用户确认购买后记账扣券。

依据应来自当次官方活动说明、券的使用说明、商品优惠明细及同账户结算预览。通用说明用于理解语义，具体适用条件从本次材料取得；材料与预览不一致时保留差异，不通过猜测改写规则。第三方攻略不作为自动写入当前规则的依据。

## 已查阅的官方依据及适用范围

### 预售协议

[淘宝/天猫官方《预售协议》](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_tmall/suit_bu1_tmall202203151048_70887.html)，页面版本更新日期为2026-09-20，2026-10-20已打开核对正文。

与本项目有关的内容：预售价格包含定金和尾款；展示的预售券后价可能变化，完整金额应核对订单；尾款可在购物车与非预售商品合并付款，但实际交易流程仍需核实。实现据此分别展示完整支出、实付定金与剩余应付，并保留结算组和变价回核。

该协议不提供所有活动统一的门槛或叠加顺序，本项目不据此自动生成满减活动。协议也涵盖天猫国际，程序本版只取国内淘宝/天猫相关部分，不覆盖跨境规则。

### 有价优惠券购买规则

[官方《有价优惠券购买规则》](https://terms.alicdn.com/legal-agreement/terms/c_platform_service_agreement/20240131203313249/20240131203313249.html)，2026-10-20已打开核对正文；页面未展示明确版本日期，不能用URL日期推定当前生效时间。

该规则说明有价券由商家设置具体商品/店铺范围和条件，相关商品券/店铺券不抵定金、运费等费用。项目将购券成本列为未支持条件，不把买券当作免费领取。此依据仅用于有价券，不能外推为所有免费券的统一叠加规则。

### 本次没有核实的事项

未核实2026双11全部活动的当前统一规则、官方立减比例、88VIP折扣顺序或各账户红包策略。一个历史跨店规则链接无法取得正文，本项目没有采纳其二手转载。没有任何默认数值因此被写入运行程序；演示中的390/345/375元仍是假设案例。

### 淘金币通用规范

[官方《淘金币通用规范》](https://terms.alicdn.com/legal-agreement/terms/common_product_agreement/20240903195440263/20240903195440263.html)，页面更新日期2024-09-12，2026-10-21已打开核对正文。规范说明实际抵扣依当次活动及提交订单页面，可能有单笔和每日限制，金币并无稳定的现金兑换关系。因此引擎只接受显式核实的积分余额、兑换步长及本次限额，不内置统一兑换比例。规范链接的玩法页本次未取得可读正文，未从中推定额外细节。

## 后续规则开发顺序

先收集一份真实淘宝/天猫购物车和优惠/结算预览，建立金额对照记录。出现尚未覆盖的规则时，按“原文/截图 → 作用范围、基数、阶段与舍入定义 → 独立可核对案例 → 程序与回归测试 → 实际预览复核”增加能力。v0.3已补齐上述直减、会员比例、多件优惠、共享红包/积分和支付折扣的计算模型。接下来用真实结算预览验证当前规则参数及分摊；指定第N件优惠、付费储值/购券成本、返现循环和退货仍需单独建模。
