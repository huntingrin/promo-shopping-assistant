# 浏览器购物车采集协议 v1

本协议规定 Agent 如何默认打开浏览器读取淘宝/天猫购物车，以及如何把结果交给本地程序。核心计算仍由 `scripts/shopping.py` 完成；浏览器是可选的采集层，不参与金额计算。

## 默认采集顺序

1. 用户已经提供截图或文字：先使用已有材料；需要复核时再打开浏览器。
2. 用户提出算购物车、没有提供材料：默认打开可见浏览器读取，不要求用户先发截图。
3. 宿主有浏览器工具但没有本地 Playwright：用宿主工具按本协议生成同格式快照。
4. 浏览器不可用、未登录且用户不愿登录、或被风控阻断：回退到截图/文字，并说明原因。

“任何 Agent 默认打开浏览器”是能力允许时的默认行为。纯聊天宿主、没有浏览器权限的宿主或禁止访问账号页面的宿主只能回退。

本地适配器默认打开可见浏览器；非交互运行在采集完成后关闭自己启动的浏览器。需要让用户继续查看页面时，用 `--keep-open` 在终端运行，或改用宿主自带浏览器工具。CDP 附加模式不会关闭用户原有浏览器。

## 登录与会话

- 优先使用独立、持久的浏览器配置，首次由用户扫码/验证，之后复用。
- 支持两种模式：
  - **独立配置**：默认；不读取用户日常浏览器的 Cookie，权限最小。
  - **CDP 附加**：可选；用户以远程调试端口启动 Chrome 后，通过 `--cdp-url` 复用现有登录态。此模式会接触用户日常配置，必须由用户主动开启。
- 未登录时打开登录页，明确告诉用户“请在打开的浏览器里扫码登录，完成后我会继续”。
- 不询问、不记录、不代填账号密码；不绕过验证码、滑块或风控。
- 等待超时后停止，不反复重试冲击平台。

Playwright 不能直接接管 macOS 默认的 Safari，也不能直接读取日常 Chrome 的 Cookie。需要 Safari 的场景不在当前适配器范围。

## 只读红线

允许：

- 打开购物车、商品详情、优惠/券说明、只读结算预览。
- 滚动、展开说明、读取 DOM/可见文本/页面结构化数据。
- 勾选商品，以及点击“结算”进入预览；进入前告知用户，结束后恢复原勾选。
- 读取运费、优惠分摊和应付金额。

禁止：

- 提交订单、付款、确认收货。
- 删除商品、修改数量、加购、领券、修改地址、保存支付方式。
- 输入密码、代过验证码、绕过风控。
- 读取订单历史、地址簿、支付方式、消息等与本次算账无关的账号数据。

结算预览不是购买。只有用户明确确认已购买后，才通过 `purchase` 记账。

## 采集页面与字段

### 购物车

- 商品名称、SKU/规格、数量。
- 页面展示价及价格标签（活动价、券后价、到手价、尾款等）。
- 店铺名称、淘宝店/天猫店类型。
- 勾选状态（只用于理解当前选择，不等同于“必买”）。
- 页面可见的优惠、券、红包、淘金币、预售、包邮/运费文案。
- 商品链接和采集时间。

### 商品详情

只为购物车中的商品补全 SKU、活动价、预售定金/尾款、单品优惠。只读打开，不点击加购。

### 优惠/券说明

只打开“使用说明”“活动规则”“优惠详情”“查看明细”等说明入口，不点击“领取/领券”。记录门槛、减免、范围、有效期、次数、互斥/叠加说明的原文。

程序不会根据优惠名称猜参数。缺少门槛、减免、基数、执行方式或叠加条件时，保存原文并生成阻塞问题。

### 结算预览

- 允许选中商品并点击“结算”进入只读预览。
- 只读取商品、运费、优惠分摊、应付金额等算账字段。
- 不点击“提交订单”“立即支付”“确认付款”。
- 不保存收货地址、手机号、支付信息。
- 采集结束尝试恢复原勾选；恢复失败必须提示用户。

## 快照格式

适配器输出 `cart-snapshot.json`。任何宿主浏览器工具都可以生成同样结构。

```json
{
  "schema": "promo-shopping-assistant/cart-snapshot",
  "schema_version": 1,
  "captured_at": "2026-10-21T18:00:00+08:00",
  "title": "淘宝天猫购物车",
  "source": {
    "kind": "browser",
    "url": "https://cart.taobao.com/cart.htm",
    "browser": "chrome",
    "mode": "persistent"
  },
  "login": {"required": true, "completed_at": "2026-10-21T17:59:00+08:00"},
  "pages": [
    {"kind": "cart", "url": "https://cart.taobao.com/cart.htm", "captured_at": "..."}
  ],
  "cart": {
    "version": 1,
    "items": [
      {
        "id": "lamp",
        "name": "台灯",
        "spec": "暖白光",
        "platform": "taobao",
        "marketplace": "tmall",
        "shop": "B",
        "quantity": 1,
        "price": "199.00",
        "price_text": "活动价 ¥199.00",
        "price_label": "活动价",
        "price_kind": "before_order_promotions",
        "url": "https://detail.tmall.com/item.htm?id=10002",
        "source": {"kind": "browser", "page": "cart", "text": "活动价 ¥199.00"}
      }
    ],
    "promotions": [],
    "shipping": []
  },
  "promotion_hints": ["B店满200减25券"],
  "checkout": {
    "captured": true,
    "url": "https://buy.taobao.com/...",
    "summary_lines": ["商品合计 ¥199.00", "运费 ¥0.00", "应付 ¥174.00"]
  },
  "questions": [],
  "warnings": []
}
```

### 字段约束

- `schema_version` 必须为 `1`。
- `cart.items` 至少提供 `id`（或可由 URL/标题稳定生成）；`price` 或 `price_text` 至少一个。
- `price_kind` 只能是 `before_order_promotions`、`after_coupons`、`tail_payment`、`unknown`。
- `cart.promotions` 只放已经能表达的规则；不完整的优惠原文放 `promotion_hints` 或 `questions`，不要猜。
- `source` 记录页面 URL、页面类型、观察时间和关键原文；不记录密码、Cookie、地址、手机号、支付信息。
- `pages` 只放页面元数据和可选截图路径，不放大段页面正文。
- 未知字段会被拒绝，避免拼写错误静默丢数据。

## 价格口径

| 页面文字 | `price_kind` | 处理 |
| --- | --- | --- |
| 活动价、售价、原价、标价 | `before_order_promotions` | 可计算 |
| 购物车展示价、页面价 | `before_order_promotions` | 可计算，但必须带“结算预览复核”的假设 |
| 券后价、到手价、预估到手价、折后价 | `after_coupons` | 阻塞，要求补优惠前价格 |
| 尾款、定金 | `tail_payment` | 阻塞，要求补完整售卖价和已付定金 |
| 无法判断 | `unknown` | 阻塞，不猜 |

同一页面出现多个金额且没有标签时，不要任选一个；保存原文并提问。

## 优惠与运费

- 只有页面或说明明确给出范围、门槛、减免、基数、执行方式、次数和叠加关系时，才写入 `cart.promotions`。
- 页面出现优惠文案但参数不全时，写入 `promotion_hints`，由导入层生成待核实问题；不要静默忽略。
- 运费必须按店铺确认；结算预览只显示合计时，不能拆成各店运费。确认包邮后再写 0 元。
- 红包/淘金币/会员额度等共享资源，只有页面明确显示余额、兑换步长和本次限额时才录入。

## 导入任务

```bash
python3 scripts/shopping.py import-cart TASK_DIR --snapshot cart-snapshot.json
python3 scripts/shopping.py compare TASK_DIR --format text
```

- 任务不存在时创建；已存在时按商品/优惠/运费 ID 合并，保留用户手工修正过的其他商品。
- 快照中的缺失字段生成阻塞问题；`status=imported` 只表示资料已保存，不表示已算出金额。
- 采集时间写入 `data_as_of`；旧结果会因资料变化失效。

## 证据与隐私

- 默认只保存算账字段、URL、观察时间和关键原文。
- 截图是可选项，保存在任务目录的 `evidence/`；可能包含个人信息，只留在本地，不上传。
- 地址、手机号、证件号、邮箱、支付信息不落盘；适配器会对结算预览和原文做脱敏。
- 浏览器配置目录与代码仓库分离，权限 `0700`，不提交 Git。
- 任务目录包含购物记录和截图，用户应自行决定保留期限。

## 失败与回退

| 情况 | 默认处理 |
| --- | --- |
| Playwright 未安装 | 提示安装；改用宿主浏览器工具或截图 |
| 没有 Chrome/Edge | 提示安装或使用 Playwright Chromium |
| 未登录 | 打开登录页，等用户扫码/验证后继续 |
| 验证码/风控 | 停在当前页，等用户完成；不绕过、不猛重试 |
| 页面结构变化 | 保留已读字段和原文，提示需要人工核对 |
| 结算预览失败 | 保留购物车资料，运费/金额转人工补问 |
| 用户拒绝登录 | 回退截图/文字，不继续访问账号 |

## 验证限制

适配器的选择器、登录流程和页面结构需要在真实淘宝/天猫账户上手工复核。自动化测试只能覆盖快照转换、价格口径、去重、脱敏和本地 mock 页面，不能证明当前平台页面结构或账户资格。
