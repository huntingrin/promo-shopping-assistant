# v0.4.0 验证记录

日期：2026-10-21。运行环境的精确版本与自动化测试结果见 [test-run.txt](test-run.txt)。所有金额案例均为假设输入。

## 已验证

- `python3 -m unittest discover -s tests -v`：安装 Playwright 后126项测试通过；未安装 Playwright 时122项运行、121项通过、浏览器 mock 测试跳过。包括原内核22项、任务/CLI、淘宝天猫适配、扩展折扣、浏览器快照导入16项和适配器辅助函数/本地 mock 页面测试。原内核包含50组随机购物车，扩展引擎另有40组随机购物车，均以固定种子和独立穷举算法交叉核对。
- 浏览器快照可创建新任务或合并到已有任务；`source.kind=browser`、采集时间、商品/优惠/运费数量正确写入，旧结果在导入后失效。
- 快照中“活动价/售价”映射为优惠前价；“购物车展示价”带复核假设；“券后/到手/预估”映射为券后价并阻止重复扣券；无标签价格映射为未知并生成阻塞问题。
- 不完整优惠、未匹配商品的优惠范围只生成待核实问题，不静默计入金额；已完整覆盖的优惠文案不会重复提示。
- 地址、手机号、证件号、邮箱和地址文本在导入时脱敏；快照中的未知字段被拒绝，避免隐私字段或拼写错误静默进入任务。
- 适配器辅助函数覆盖价格解析、价格口径、脱敏、原文去重和稳定ID；本地 mock 页面验证了购物车 DOM 提取、登录/风控标记和适配器 CLI 生成本地快照。
- 比例基数独立于门槛基数；并行/顺序折扣、逐件/整单舍入、向下/四舍五入/向上取整、单件和整单封顶、最低实付、满件档位及每N件减额均有覆盖。
- 会员累计额度、红包金额和积分数量在拆单间共享；积分只能使用已核实的完整兑换步长，余额、次数和商品数量在已购后同时扣减。实际权益消耗不符时拒绝记账且保留原任务。
- 支付阶段抵扣运费的开关、支付折扣不重算包邮、定金保护、自动有限额度的结算顺序、获批纯凑单前置及受限搜索都有覆盖。不能跳过前一步沿用依赖已消耗自动额度的后一步。
- 缺失比例/舍入/余额/积分兑换条件，或明确未知的最低实付参数时保留草稿、提出阻塞问题；无关且未被选入方案的未完成资源不阻塞计算。资源单位不能用同一ID从金额改为积分。
- 新演示 `demo --discounts`：100元商品按假设的15%立减、剩余金额5%会员减免、10元红包与剩余应付5%的积分抵扣后，现金67.22元，消耗红包10元和353积分。
- 独立验证Agent从自然语言材料建模，另行枚举13种有序拆单、484组权益组合；1/2/3次结算最低分别为320.26/318.26/324.26元，与程序一致。两次记账后的余额与现金合计也一致，超额积分凭据被拒绝。过程与边界见 [FORWARD_TEST.md](FORWARD_TEST.md)。
- Skill 创建工具的 `quick_validate.py`：入口元数据、名称及脚手架检查通过。
- 原清单、明确批准清洁布后的最低支出和最少操作方案分别为390元/1次、345元/2次、375元/1次。
- 预售案例：完整支出720元、已付100元、本次应付620元。
- 从任意工作目录运行CLI，整体复制脚本和案例后可以独立运行，不依赖相邻研究目录。
- 任务流程：创建、读取、批准具体候选、求解、记录已购、扣减数量及账户券次数、再次求解剩余商品。
- 第一单200元记账后，剩余最省方案145元；结果同时显示已购200元、剩余145元及整次预计345元。
- 已消耗优惠的余额在商品/规则清理后保留；重新添加同ID优惠且未重新指定余额时，不恢复已用掉的券。
- 修改价格、数量、商品选择、偏好和券次数后重新计算；更新清空当前结果，历史仍保留。
- 资料版本冲突拒绝写入；直接修改输入后指纹失配，隐藏旧结果。
- 缺价格、运费、优惠条件或存在未解决关键问题时不返回金额方案；超规模清单保留全部资料。
- 无效输入和超时返回明确状态；比较失败替换旧结果，不返回部分方案冒充完整结果。
- 不同结算组的最少次数约束、同基准净节省、负数节省到分、来源缺失提示、实际结算差异补问。原通用内核的跨平台测试仍保留，不表示产品支持其他平台。
- 原子写文件、同任务并发锁、凭据ID去重和实际用券校验。
- `build_release.py` 生成可整体迁移的zip及SHA-256；解压包独立运行演示和测试，分发内容不含任务、Git目录、浏览器配置、截图或缓存。
- 淘宝/天猫别名规范化为同一交易域，已确认同组的两类店铺不被误拆；天猫专属券不统计淘宝店的金额。
- 店铺类型过滤与店铺、SKU、标签以AND共同匹配；类型未知且影响用券时阻止求解，核实后恢复。
- 淘宝/天猫混合结算组中的账户券次数仍共享，不按店铺类型重复发券；天猫别名运费更新不会新增重复配置。
- 其他平台、天猫国际及矛盾店铺类型明确拒绝；失败更新不修改任务。
- 券后价、尾款或未知价格口径不会被再次扣券；适配版本加入指纹，v0.1旧结果失效。

## 尚未验证/尚未实现

- 尚未使用真实淘宝/天猫账户验证浏览器适配器的选择器、登录扫码流程、券说明弹层、商品详情页和只读结算预览；本地 mock 页面不能证明真实页面结构。
- Playwright 不能接管 macOS 默认 Safari，也不能直接读取日常 Chrome 的 Cookie；当前默认用系统 Chrome/Edge + 独立配置，首次登录一次。CDP 附加模式尚未在真实 Chrome 调试端口上验证。
- 尚未使用真实购物车和平台结算预览验价，也未进行目标用户试用。
- 尚未在多种品牌 Agent 中分别验证自动发现、浏览器工具接入、截图回退及跨对话恢复；这些能力依赖宿主与具体工具。
- CLI已在当前macOS/Python环境测试；代码以Python 3.10+标准库编写，尚未逐一实测其他Python版本、Windows和Linux。
- 没有自带OCR或自然语言模型；宿主Agent按Skill整理输入，确定性计算与状态管理由程序实现。
- 买一赠一/指定第N件折扣、付费储值本金与购券成本、返现/赠券循环、退货凑单及加购预算约束没有建模。
- 已核对官方预售协议、有价券规则和淘金币通用规范的相关正文，来源与适用边界见 [淘宝天猫规则参考](../references/taobao-tmall.md)。当前官方立减、会员、红包/金币及支付优惠的资格、比例、基数、舍入、分摊和顺序仍须由当次材料确认；未核实2026双11完整活动规则。

金额示例都是假设情景，不是任何平台当前报价。自动化通过证明本次覆盖范围内的程序行为，不代表真实平台完整规则或各宿主体验已验证。
